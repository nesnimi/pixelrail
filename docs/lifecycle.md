# Переключение релизов PixelRail

`deploy.sh --apply` теперь активирует новый PixelRail в текущем Wayland-сеансе:
сначала копирует release и делает backup, затем запускает его и проверяет
`menus.status` через IPC по точному PID. После успешного переключения файлов
останавливает прежние экземпляры PixelRail через `qs kill --id`.
Перезагрузка Hyprland, запуск остальных программ и системных служб не выполняются.

При отказе запуска прежние процессы и entrypoints остаются. Неудачная попытка
помечается в manifest, её новые процессы завершаются; release и backup сохраняются.
Если ошибка возникла уже при остановке старого экземпляра, команда сообщает
неуспех, сохраняет рабочий новый release, backup и `runtime_error` для диагностики.
Принудительный SIGKILL не используется.

`rollback.sh --apply` сначала запускает прежний release и проверяет IPC, затем
восстанавливает файлы и останавливает заменённые экземпляры. Если прежний release
не стартует, текущий продолжает работать, откат можно повторить после исправления.
При откате первой установки без предыдущего управляемого release PixelRail
останавливается, а исходные файлы восстанавливаются. Старые backup поддерживаются:
путь предыдущего release извлекается из сохранённой ссылки pixelrail-shell.

Для offline-установки, другого HOME и тестового staging:

```bash
./scripts/deploy.sh --target-home "$PWD/.cache/staging-home" --apply --no-start
./scripts/rollback.sh --target-home "$PWD/.cache/staging-home" --apply --no-start
```

Без `--apply` сохраняется dry run. `--no-start` не обращается к Quickshell вообще.
Рабочие настройки автоматически в ходе разработки не применялись.

Один общий flock в XDG_RUNTIME_DIR сериализует deploy, rollback и pixelrail-shell
для одного HOME и Wayland-дисплея (абсолютное и относительное имя socket нормализуются). Зависимости — уже используемый Python3 и
его стандартная библиотека; отдельная утилита flock не нужна.
Автозапуск не создаёт процесс, если текущий экземпляр уже отвечает на IPC.
Новый lifecycle-скрипт, вызванный из старого release, выбирает установленный release;
явное PIXELRAIL_QML по-прежнему позволяет указать другой конфиг для диагностики.

Остановка ограничена точными путями QML из manifest PixelRail и текущего исходного
дерева. Перед остановкой повторно сверяются ID, PID и config_path в реестре qs.
Имя процесса, подстрока pixelrail и одно лишь расположение внутри releases не
являются основанием для остановки. Неизвестные экземпляры сохраняются, общий
pkill/killall не используется. Выбор экземпляров qs ограничен текущим дисплеем
(без --any-display). Старые, уже скопированные версии скриптов без lifecycle.py
не обновляются задним числом — использовать установленный ~/.local/bin/pixelrail-shell.

Проверки:

```bash
python3 tests/deployment.py
python3 tests/lifecycle.py
python3 tests/lifecycle-runtime.py
python3 tests/menu-routing.py
```

Первые два теста используют временный HOME и подставной qs, не управляют рабочей
сессией. Runtime-тест использует настоящий Quickshell с отдельным HOME/runtime и
минимальным QML без поверхностей: проверяет IPC, обновление/откат, отказ запуска,
повторный старт и сохранность постороннего экземпляра. Дизайн QML и бинды не меняются.

Предыдущие инструкции о ручном завершении старого release при обычном deploy/rollback
заменены этим механизмом. При аварийном прерывании установки backup и manifest
остаются для ручного восстановления; произвольные неизвестные qs-процессы не удаляются.

После успешного handoff выполняется событийный reconcile выбранной панели (по умолчанию Waybar).
Он не меняет сохранённый режим, не запускает qs повторно и завершает только зарегистрированную
Waybar своего сеанса. Подробности: [Pixel Sidebar](sidebar.md).
