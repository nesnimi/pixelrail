# Pixel Clipboard v2.0

Super+V и IPC `menus.open clipboard` сохранены. Панель работает в существующем
Quickshell-процессе и создаётся лениво. Launcher, бинды, Waybar, SwayNC и механизм
переключения release не менялись.

## Причина задержки и измерения

Старый путь: `cliphist list` → поиск ID → `cliphist decode` →
`subprocess.run(wl-copy, stdout=PIPE, stderr=PIPE, timeout=8)`.
По умолчанию wl-copy форкает долгоживущего владельца Wayland clipboard. Его
унаследованные pipe оставались открытыми: Python communicate() ждал EOF, хотя
clipboard уже был доступен. Через 8 секунд UI получал timeout вместо подтверждения.

Это воспроизведено настоящими cliphist/wl-copy/wl-paste на приватном Wayland
ext-data-control сервере, без доступа к рабочему буферу. Пример измерений:

| Этап | До исправления | После |
|---|---:|---:|
| cliphist list | 5,34 мс | 4,87–6,14 мс при открытии |
| Разбор списка | 0,015 мс | около 1 мс, с классификацией картинок |
| cliphist decode | 2,34 мс | около 2,2 мс |
| Ожидание wl-copy | 8009 мс, timeout | около 3,7 мс |
| Clipboard доступен до старого timeout | через 37 мс | без многосекундного ожидания |
| Полный запуск Python-обработчика для текста | старый путь ~8018 мс | около 60 мс |
| QML: выбор → callback обработчика | старый путь блокировался ожиданием | 77 мс в скрытом native-интеграционном тесте |

Для повторных вызовов restore внутри прогретого Python измерялось 6–28 мс,
в зависимости от текущей нагрузки. Это замеры тестовой среды, не гарантия времени
в каждом приложении. QML JSON/model binding занимал 1–2 мс. Физическое отображение
и системный фокус на целевом Hyprland остаются ручной приёмкой; fade 140 мс не входит
в время callback. Последние результаты: `.cache/clipboard-latest.json`, baseline
с timeout — `.cache/clipboard-benchmark.json`.

Теперь запись декодируется непосредственно по ID, без повторного list. Оригинал
проходит через анонимный временный файл в wl-copy; захватываемых pipe stdout/stderr
нет. Ожидается завершение стартового родителя wl-copy — не завершение владельца.
Не используются --paste-once или --foreground, владелец не убивается ради скорости.
Нативные тесты проверяют несколько paste после завершения helper и Quickshell.

Диагностические замеры отключены по умолчанию. `PIXELRAIL_CLIPBOARD_TRACE=1` перед
штатным запуском shell включает этапы list/parse/decode/MIME/copy в helper и время
QML callback/model. Содержимое clipboard не логируется. Переменная должна попасть
в окружение запущенного shell; повторный no-duplicate старт не меняет его окружение.

## Изображения и MIME

Текстовые и графические записи имеют разные карточки. Для PNG/JPEG/WebP показываются
миниатюра, тип и размеры; техническая строка binary data не служит названием.
Поддерживаются и другие распознаваемые форматы установленных GdkPixbuf loaders.
Особенность cliphist: WebP и некоторые другие изображения могут иметь сырой RIFF/
бинарный preview вместо строки binary data — такие записи распознаются по заголовку.

При выборе копируются **оригинальные байты cliphist decode**, не путь и не превью.
PNG/JPEG/WebP получают соответствующий image MIME; текст — UTF-8. Для остальных
изображений тип определяется GdkPixbuf, для прочих binary сохраняется native type
inference wl-copy. Cliphist не хранит весь первоначальный набор MIME-представлений;
например, полное восстановление одновременно HTML и plain text не обещается.

Оригинал не передаётся в QML и не сохраняется в preview-кэше. Временные payload
анонимны и удаляются ОС даже при завершении helper. Миниатюры — PNG до 512×384.
Повреждённая/удалённая запись показывает понятную ошибку. Ошибка превью не запрещает
копирование доступного оригинала. Отсутствующий/эвиктированный кэш регенерируется.

Один thumbnail helper обрабатывает только видимые карточки. Прокрутка/поиск
пересчитывают спрос, без накопления очереди на всю историю. Qt image cache выключен
для карточек; после закрытия lazy-панель освобождается. Активное подтверждённое
копирование/применение завершается асинхронно даже при скрытии окна, чтобы Escape
не оборвал уже начатую запись состояния или clipboard ownership.

Кэш: `$XDG_CACHE_HOME/pixelrail/clipboard`, по умолчанию ~/.cache/pixelrail/clipboard.
Ограничения — 256 миниатюр и 64 МиБ вместе с метаданными, вытеснение старых по LRU.
Ревизия базы входит в ключ: изменение базы/повторное использование ID не возвращает
старые pixels. Каталог закрыт правами 0700, файлы — 0600. Превью содержат частные
данные; удалить этот каталог вручную можно без удаления самой cliphist DB.
Очистка выполняется при работе с превью, постоянного polling/демона кэша нет.

## Один watcher для текста и изображений

Старый запуск содержал `wl-paste --type text --watch cliphist store`, поэтому
изображения не сохранялись этим watcher. Теперь используется один
`wl-paste --watch cliphist store`, автоматически выбирающий доступный MIME.

`pixelrail-clipboard-watch` — короткая команда управления существующим watcher,
а не новый демон. Под общей блокировкой для дисплея она:

- сохраняет уже работающий native watcher;
- заменяет точный прежний text-only вызов на общий;
- удаляет дубли известных вызовов после проверки UID/argv/времени рождения/дисплея;
- не трогает неизвестный пользовательский cliphist watcher: сообщает ошибку,
  предотвращая создание ещё одного. В таком случае сначала согласовать его вручную.

Команда включена в существующий pixelrail-start. После deploy можно вызвать только
её, без перезапуска остальных компонентов. Никакие системные службы не создаются.

## Установка и откат — вручную

```bash
cd ~/Projects/pixelrail
./scripts/deploy.sh                  # dry run
./scripts/deploy.sh --apply          # штатный проверенный lifecycle PixelRail
~/.local/bin/pixelrail-clipboard-watch
```

Новые файлы доставляются существующим копированием release; deploy/rollback не
переписывались. Рабочие ~/.config, ~/.local/bin, обои и clipboard при разработке
не менялись. Для staging:

```bash
mkdir -p .cache/staging-home
./scripts/deploy.sh --target-home "$PWD/.cache/staging-home" --apply --no-start
./scripts/rollback.sh --target-home "$PWD/.cache/staging-home" --apply --no-start
```

Откат рабочей версии: `./scripts/rollback.sh`, затем после просмотра
`./scripts/rollback.sh --apply`. Сама история cliphist при откате не удаляется.

## Тесты и ручная приёмка

```bash
python3 tests/clipboard-wayland.py
python3 tests/clipboard-wayland.py --benchmark  # один намеренный старый timeout ~8 с
python3 tests/qt-ui.py
python3 tests/runtime-menus.py
python3 tests/menu-backend.py
python3 tests/deployment.py
python3 tests/lifecycle.py
lua tests/binds.lua
lua tests/super-tap.lua
```

Native-тест требует уже установленные cc, wayland-scanner и заголовки
wayland-server/protocols; это только тестовые инструменты, не новые зависимости
PixelRail. Он компилирует surface-free сервер в .cache и работает с отдельным
HOME/runtime/DB. Проверены короткий/длинный Unicode и многострочный текст,
PNG/JPEG/WebP, исходные байты и MIME, многократная вставка, быстрые restore,
размер кэша, upgrade text-only watcher и четыре конкурентных старта.

Qt UI-тест использует настоящие key/mouse события в software/offscreen окне;
панельные интеграционные тесты держат окна скрытыми и сохраняют рабочий clipboard.
Для физической приёмки после установки:

1. Super+V → короткий/длинный текст, кириллица, emoji, табуляции и переводы строк.
2. Скопировать PNG и JPEG из приложения. Проверить карточки, затем восстановить
   и вставить Ctrl+V в Kitty (текст) и поддерживающее картинки приложение.
3. Проверить WebP, большой screenshot, удалённую запись/недоступную миниатюру.
4. Повторять Super+V/Enter/Esc, поиск и прокрутку длинной истории. Убедиться,
   что после выбора нет восьмисекундного состояния ожидания.
5. Проверить Wallpaper Picker: все chips, Esc после каждого взаимодействия,
   отмену без смены фона, Ctrl+Enter и повторное открытие.
6. Замерить idle CPU/RSS после закрытия на T480; физический compositor focus,
   видимое оформление, Ctrl+V в конкретном Chrome/редакторе и расход батареи
   не подменяются тестами приватного data-control сервера.
