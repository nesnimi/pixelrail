# Wallpaper Picker v2.0

Super+Ctrl+T открывает существующий IPC `menus.open wallpaper`. Теперь это сетка
с крупными превью, поиском, фильтрами «Все / Обои / Загрузки / Скриншоты» и отдельным
предпросмотром. Остальные меню, Launcher v1.1, бинды и lifecycle deploy/rollback
не менялись. В рамках разработки рабочие обои и ~/.config не изменялись.

Фильтры оформлены как MD3 chips: высота 36 px, горизонтальные отступы 14 px,
интервал 8 px, pill-форма и заметное активное состояние. Escape обрабатывается
одним WindowShortcut независимо от focus вкладки/поиска/сетки/предпросмотра;
он и кнопка закрытия используют один closeRequested. Без применения фон не меняется.
Проверка настоящими Qt key/mouse событиями: `python3 tests/qt-ui.py`.

## Где ищутся изображения

По умолчанию: ~/Pictures/Wallpapers, ~/Pictures, ~/Downloads. Дополнительно
учитываются локализованные XDG_PICTURES_DIR и XDG_DOWNLOAD_DIR: сначала окружение,
затем файл user-dirs.dirs. Отключённый XDG-каталог, указывающий прямо на HOME,
пропускается, чтобы не сканировать весь домашний каталог.

Дополнительные папки читаются из `$XDG_CONFIG_HOME/pixelrail/wallpapers.json`
(обычно ~/.config/pixelrail/wallpapers.json). Пример в репозитории:
[wallpapers.example.json](../config/pixelrail/wallpapers.example.json).
При необходимости оператор вручную создаёт конфиг:

```json
{
  "directories": ["~/Wallpapers", "/mnt/Images/Фоны"],
  "max_depth": 4
}
```

Пути должны быть абсолютными или начинаться с ~/; поддерживается $HOME.
Ничего автоматически в ~/.config не копируется. Пакеты устанавливать не нужно.
Некорректный JSON/тип параметра показывается как ошибка в панели.

Рекурсивный обход выполняется только при открытии меню; глубина по умолчанию 4,
разрешено 0…8. Скрытые папки, node_modules, venv и symlink-каталоги не обходятся.
Отсутствующие/недоступные каталоги пропускаются. Пересекающиеся каталоги и ссылки
на один файл не дублируют результат; файлы по ссылкам вне заданных корней исключаются.
Не задавайте HOME или /: такие дополнительные корни отвергаются.
После загрузки нового файла закройте и снова откройте меню — polling отсутствует.

Обои и обычные изображения идут первыми, Downloads следом, скриншоты последними.
Скриншоты определяются по папкам Screenshots/«Скриншоты»/«Снимки экрана» и префиксам
Screenshot/«Скриншот». Внутри группы новые файлы идут первыми. Это классификация по
пути/имени, а не распознавание содержания картинки.

## Форматы и производительность

Список форматов берётся из установленной GdkPixbuf — той же библиотеки, с которой
связан swaybg. Здесь доступны PNG/JPG/JPEG/WebP и, среди прочих, BMP, GIF, AVIF,
HEIF, TIFF, SVG. Конкретный формат/вариант файла должен декодироваться установленным
loader. Анимированные форматы используются как статическое изображение.
Некорректное изображение даёт ошибку предпросмотра, без изменения текущего фона.

Нативный helper через Python ctypes использует уже установленную библиотеку;
новые Python-пакеты или графические утилиты не требуются. Превью преобразуются
в PNG до 512×384, поэтому отсутствие WebP/AVIF-плагинов Qt не мешает сетке.
EXIF-ориентация учитывается. Кэш:
`$XDG_CACHE_HOME/pixelrail/wallpapers` (обычно ~/.cache/pixelrail/wallpapers).
Ключ учитывает путь, размер и время изменения исходника. Кэш можно удалить вручную:
он восстановится при последующем просмотре; исходные изображения не затрагиваются.
Автоматического ограничения дискового кэша пока нет.

Один thumbnail-процесс обрабатывает выбранный элемент и текущий viewport сетки,
пересчитывая спрос после каждого задания. Быстрая прокрутка не накапливает очередь
на сотни файлов. GridView создаёт видимые карточки; QML получает уменьшенные PNG,
а не полноразмерные оригиналы, и отключает image cache для скрытых карточек.
После закрытия lazy-панель освобождается. Постоянных таймеров/polling не добавлено.
Декодер может временно загрузить один оригинал: размер его рабочих буферов зависит
от формата. Численные показатели RSS/батареи на UHD 620 требуют ручного замера.

## Выбор и применение

- Щелчок по карточке / стрелки — выбор и предпросмотр, без применения.
- Enter — перевод фокуса в предпросмотр.
- «Применить» / Ctrl+Enter — применение выбранного изображения.
- Esc — закрыть; Tab — обычный переход между элементами управления.
- Длинное имя обрезается в карточке, целиком доступно в tooltip; кириллица и
  специальные символы передаются через JSON/argv, без shell-интерполяции.

Существующий механизм сохраняется: swaybg с режимом fill. Его запуск теперь
сериализован общим lock на Wayland-дисплей. PID, время рождения и argv хранятся
в `XDG_RUNTIME_DIR/pixelrail-swaybg-*.json`; остановка идёт через pidfd после
проверки процесса. Общего pkill swaybg больше нет. Старый точный вызов PixelRail
с прежним выбранным изображением или цветом #101827 принимается под управление.
Если обнаружен другой swaybg на этом дисплее, применение отклоняется с понятной
ошибкой: чужой процесс нужно остановить/согласовать вручную.

Сначала декодируется превью, затем завершается прежний фон и запускается один новый.
Через короткую проверку живого процесса сохраняется выбор атомарно в
`$XDG_STATE_HOME/pixelrail/wallpaper`. При ошибке старта старый выбор остаётся,
и прежний swaybg запускается снова. Проверка подтверждает процесс, а не наличие
отрисованного кадра — видимую работу на compositor нужно проверить вручную.

`pixelrail-wallpaper` при следующем входе восстанавливает этот файл; прежний
~/.config/pixelrail/wallpaper остаётся read-only совместимым источником.
Повторный/конкурентный запуск не создаёт дополнительные экземпляры.
Перезагрузка для применения не нужна.

После успешного применения shell испускает `wallpaperChanged(string path)`: он
запускает [Material You Theme Engine](material-you.md), который обновляет цвета
Quickshell без перезапуска. При отмене или ошибке сигнала нет. Кнопка закрытия
в шапке удалена; Escape по-прежнему закрывает галерею из любого состояния.

## Проверки

```bash
python3 tests/wallpapers.py
python3 tests/qt-ui.py
python3 tests/menu-backend.py
python3 tests/runtime-menus.py
python3 tests/deployment.py
python3 tests/lifecycle.py
lua tests/binds.lua
lua tests/super-tap.lua
/usr/lib/qt6/bin/qmllint quickshell/components/WallpaperView.qml quickshell/components/MenuPanel.qml quickshell/shell.qml
```

Тесты используют временные HOME/config/cache/runtime внутри репозитория и fake swaybg.
Реальный Quickshell проверяется со скрытыми окнами: 120 изображений в сетке,
ограниченная генерация превью, Downloads-фильтр, стрелки, Ctrl+Enter, сохранение
выбора и сигнал смены обоев. Backend в runtime-тесте получает отдельное имя дисплея,
чтобы не обращаться к рабочему swaybg. Смена реальных обоев не выполняется.

Ручная приёмка после добровольного подключения:

1. Положить PNG/JPEG/WebP в Downloads и Pictures/Wallpapers, картинку в Screenshots,
   добавить каталог с кириллицей через конфиг. Открыть Super+Ctrl+T.
2. Проверить все четыре фильтра, поиск по длинному имени, tooltip, прокрутку,
   большие превью и повреждённый файл. Просмотр и Esc не должны менять фон.
3. Проверить стрелки, Enter, Ctrl+Enter и кнопку применения. Убедиться, что на
   дисплее работает один swaybg и старые процессы не накапливаются после смен.
4. Закрыть/открыть picker и повторно войти в сеанс: выбор должен сохраниться.
5. Проверить 1366×768, несколько мониторов, масштаб, idle CPU/RSS после закрытия.
   Производительность на целевом GPU и физические клавиши автоматически не измерялись.
6. Проверить Launcher, справку, clipboard и остальные меню; deploy/rollback по
   [существующей инструкции](lifecycle.md), для staging обязательно --no-start.

Откат — сохранённый release через rollback.sh. Если нужно вернуть прежние обои,
достаточно выбрать их в picker; исходники и прежний config-файл не удалялись.

В v2.5 дисковый thumbnail cache ограничен 512 PNG / 128 MiB; prune выполняется
под lock при catalog/new thumbnail, не в UI и не на таймере. Cache-hit не
перекодирует PNG и сохраняет mtime. Вытесненное превью лениво восстанавливается
при Image.Error; исходник/выбор обоев не меняется. Подробности: [performance.md](performance.md).
