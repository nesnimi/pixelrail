# PixelRail без Rofi

Rofi больше не нужен для меню и launcher. Pixel Launcher v1.1, QML,
бинды Super, языковые раскладки и оформление не изменены.

## Что изменилось

`pixelrail-menu` вызывает `menus.open`, launcher — `launcher.toggle`.
Меню keys, clipboard, command, windows, controls, power, wallpaper, media,
emoji и псевдоним session сохранены. IPC hide/status сохранён.
Переменные PIXELRAIL_UI и PIXELRAIL_LAUNCHER больше не выбирают backend.
Старый pixelrail-launcher-rofi и scripts/fallback/* — совместимые обёртки
нативных меню; исполняемых вызовов Rofi в них нет.

Автозапуск: hyprland.start → pixelrail-start → pixelrail-shell.
При отказе IPC, отсутствии QML/бинарника или ошибке старта меню возвращает
код 1, пишет инструкцию в stderr и, если
notify-send уже установлен, показывает уведомление. Автоматического запуска
терминала, перезапуска shell или фонового опроса нет. Неизвестное меню: код 2.

Deploy не устанавливает пакеты и больше не копирует темы в .config/rofi.
Миграция точной старой строки Waybar `rofi -show drun` сохранена: она заменяет
её вызовом pixelrail-launcher. Произвольные пользовательские команды не меняются.
Каталог rofi/ сохранён как неиспользуемый архив тем; существующие темы пользователя
и старые release/backup не удаляются.

## Перед удалением пакета

1. Вручную разверните новую версию: сначала `./scripts/deploy.sh` (dry run),
   затем после просмотра `./scripts/deploy.sh --apply`. Сохраните Rollback ID.
   Автоматического применения или перезапуска нет.
2. Остановите предыдущий экземпляр по его точному пути QML или PID (не общий
   pkill). Repo и разные release имеют разные пути и могут создать два экземпляра.
   В терминале Super+Return выполните `~/.local/bin/pixelrail-shell`.
   Проверьте одиночный Super, Super+/, все меню и повторный вход в сеанс.
3. Проверьте собственные бинды, Waybar, пользовательский автозапуск и сторонние
   скрипты на оставшиеся вызовы Rofi. Репозиторий не управляет произвольными
   пользовательскими командами и не проверяет их автоматически.
4. Узнайте точное имя пакета и зависимости без изменения системы:

   ```bash
   pacman -Q rofi rofi-wayland
   pacman -Qi rofi
   ```

   В этой системе оба запроса имён указывают на пакет `rofi`; не нужно удалять
   его дважды. Если имя отличается, используйте имя из локальной базы пакетов.
   После проверки списка «Required By» и сторонних пользователей пакета оператор
   может самостоятельно выполнить `pacman -R rofi` с правами администратора.
   Это инструкция, команда удаления в ходе разработки не выполняется.
   Не добавляйте `--nodeps`, `--noconfirm` или удаление зависимостей; просмотрите
   предлагаемый список перед подтверждением. При отказе из-за зависимостей сначала
   разберите их, не обходите проверку. Пользовательские темы удалять не требуется.

## Восстановление через терминал

Откройте Super+Return (Kitty), затем:

```bash
~/.local/bin/pixelrail-shell
~/.local/bin/pixelrail-launcher
~/.local/bin/pixelrail-menu controls
```

Если запуск завершается ошибкой, проверьте `command -v qs quickshell`, вывод
команды и существование QML в release. Для диагностики с выводом на переднем плане:

```bash
qs -p /абсолютный/путь/к/release/quickshell/shell.qml
```

При альтернативном имени бинарника используйте quickshell. PIXELRAIL_QML должен
указывать на существующий shell.qml; ошибочное переопределение нужно исправить
или убрать. Из репозитория можно выполнить `./scripts/pixelrail-shell` и
`./scripts/pixelrail-menu controls`. Используйте один и тот же путь QML для
shell и IPC. Разные release считаются отдельными экземплярами.

Если Kitty по бинду недоступен, используйте уже открытый терминал или TTY.
Недостающий Quickshell восстанавливается пользователем; автоматической установки нет.

## Rollback и изолированная проверка

```bash
./scripts/rollback.sh --id ID
./scripts/rollback.sh --id ID --apply
```

Rollback восстанавливает прежние файлы, ссылки и права, включая старую команду
Waybar, если она была заменена; может вернуть зависимость от Rofi. Он отказывается
затирать изменения после deploy. Release и backup сохраняются. Перезапуск сеанса
выполняется вручную. Откат к старому release после удаления пакета может потребовать
его ручного восстановления или повторного развёртывания новой версии.

Для проверки без живой конфигурации создайте временный HOME внутри .cache и
передайте один и тот же абсолютный путь в `--target-home` обеим обёрткам;
`--apply` изменит только этот тестовый HOME. Автоматический набор:

```bash
python3 tests/deployment.py
python3 tests/menu-routing.py
python3 tests/launcher-routing.py
python3 tests/menu-backend.py
python3 tests/runtime-menus.py
lua tests/binds.lua
lua tests/super-tap.lua
```

Runtime-тест требует установленный Quickshell и доступный Wayland; панели скрыты,
опасные системные действия заменены тестовыми командами. Физические нажатия,
видимое поведение и запуск после перезагрузки остаются ручной проверкой.

## Итоговый аудит и границы проверки

| Место | Итог |
|---|---|
| pixelrail-menu / pixelrail-launcher | только IPC, без backend-переключателей на Rofi |
| pixelrail-launcher-rofi / scripts/fallback/* | совместимые переадресации на нативные скрипты |
| hypr/, quickshell/, pixelrail-start | исполняемых вызовов Rofi нет, файлы не менялись |
| deploy.sh / deployment.py | темы не копируются, пакетные команды не выполняются |
| deployment.py: rofi -show drun | только строка для замены старой кнопки Waybar |
| rofi/ | архив вне release, не читается нативными меню |

Проверки маршрутов используют Rofi-canary: любое обращение фиксируется;
нативные пути, совместимые entrypoints и ошибки его не вызывают. Проверяется
также PATH без Quickshell, Rofi и notify-send: остаётся понятная stderr-ошибка.
Для shell проверены несуществующий родительский каталог QML и ошибка старта.
Deploy/rollback проверяются в тестовом HOME, включая работу установленных
entrypoints без Quickshell, отсутствие тем в release и сохранение тем пользователя.

Меню не работают, пока Quickshell не восстановлен; альтернативного интерфейса нет.
Уведомление об ошибке необязательно и зависит от уже установленного notify-send
и работающего сервера уведомлений; stderr доступен всегда при запуске из терминала.
Восстановление не требует нового фонового процесса или дополнительного пакета.
